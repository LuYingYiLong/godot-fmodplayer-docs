在 Godot 中测试
==============================

日常测试从 Godot 编辑器和测试菜单进入。先通过 :doc:`development` 构建并同步完整插件，再打开插件仓库中的 ``tests/project.godot``，等待资源导入后按 **F5**。

更新原生库前先关闭测试项目。只更新了脚本、翻译或资源时，也要同步插件副本，确保测试的内容与当前源码一致。

.. _testing-manual:

试听与场景交互
----------------------

.. list-table::
   :header-rows: 1

   * - 菜单入口
     - 操作与观察
   * - 空间音频、混响与几何遮挡
     - 音源自动播放；WASD 移动，左键捕获鼠标，Esc 显示鼠标。改变距离、绕过遮挡物、进入混响区域，试听音量、空间位置和混响变化。
   * - FMOD / Godot 2D 播放对比
     - 两份 WAV 内容相同，分别通过 FMOD 和 Godot 导入。用按钮单独播放、同时播放或停止，确认播放切换和停止行为。

两个场景都有“返回测试菜单”按钮。也可以在编辑器中打开 ``manual/reverb_test.tscn`` 或 ``manual/playback_compare.tscn``，按 **F6** 单独运行。

.. _testing-numerical:

一键数值回归
--------------------

在主菜单点击 **运行数值回归（8 项）**。检查静默运行，完成后显示逐项结果；返回菜单后，本次项目运行期间的最近结果仍会保留。

.. list-table::
   :header-rows: 1

   * - 检查项
     - 覆盖内容
   * - 3D 空间音频
     - 距离衰减、距离滤波、发射角度和场景保存重载。
   * - 混音矩阵
     - 矩阵步长、声道布局及无效参数处理。
   * - 总线与效果器
     - 布局保存重载、路由、Solo、效果器实例和参数更新。
   * - 频谱快照
     - 频谱数据读取和快照复用。
   * - SoundGroup
     - 播放数量限制、取消限制和无效参数。
   * - FMOD API 与资源
     - FMOD 2.04 绑定、效果器、脚本 DSP 回调和音频加载入口。
   * - Capture
     - 缓冲区读写、溢出计数、声道顺序和重新挂载。
   * - 混响
     - 默认、高通、动态参数和尾音的离线输出。

数值检查使用独立的离线音频进程，开发者无需手动启动无头模式或填写套件参数。它验证可计算的正确性，试听和编辑器交互仍按本页步骤人工检查。

检查失败会停止后续项目，菜单显示已完成结果。点击 **查看回归报告** 可打开最近一次运行目录；没有生成结果或发生超时时，先查看其中的 ``godot.log``。

.. _testing-editor:

在编辑器中检查
----------------------

.. list-table::
   :header-rows: 1

   * - 改动范围
     - 检查方式
   * - 音频资源与播放器
     - 选择播放器的 ``stream``，检查波形、展开试听、资源菜单和拖放；运行场景检查播放与停止。
   * - 混音总线
     - 在 FMOD Audio Dock 检查总线和效果器拖放、发送路由、旁路、撤销重做，以及保存后重新打开的布局。
   * - DSP 预览
     - 选择 ``tests/manual/*_preview.tres``，操作图形控件及原生参数，确认二者同步、边界值和撤销重做。
   * - 空间声学节点
     - 在 3D 场景中检查声源、混响区域和遮挡几何的 Gizmo，并运行场景试听对应变化。
   * - 界面翻译与帮助
     - 切换编辑器语言，检查属性、FMOD 菜单和内置类帮助；具体维护方式见 :doc:`translation`。

Capture 和 SpectrumAnalyzer 预览读取编辑器进程中的实例。需要观察实时数据时，将对应效果器挂到编辑器内正在试听的总线上；F5 游戏进程的音频数据不会直接显示在编辑器预览里。

记录验证结果
--------------------

在 PR 中写明测试平台、Godot 与 FMOD 版本、执行过的场景或编辑器操作，以及数值回归结果。播放与空间声学改动说明听到的变化；界面改动可附截图；性能改动保留相同配置下的前后测量。

每次回归的汇总与分项报告位于 ``tests/logs/runs/``，项目日志位于 ``tests/logs/editor.log``。日志、插件副本和历史诊断资料由 Git 忽略；提交相关日志节选即可。
